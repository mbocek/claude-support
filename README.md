# claude-support

Reusable [Claude Code](https://docs.anthropic.com/en/docs/claude-code) configuration — a generic, stack-agnostic agent set plus the commands that orchestrate it. Installable into any project.

## Design

The set is built around three ideas:

1. **Roles by phase, not by stack.** Agents are defined by what they do in the development pipeline (recon → design → implementation → verification), not by technology. Stack specifics live in each project's `CLAUDE.md`, which every agent reads first — so the same set works in a Go monorepo and a SvelteKit app.
2. **Model allocation by leverage.** Cheap fast models (Haiku) do high-frequency mechanical work; the implementation sweet spot is Sonnet; design and verification — where mistakes are most expensive — run on Opus; and one escalation-only consultant runs on the strongest available model (Fable).
3. **Verification asymmetry.** Code is generated by a cheaper model and reviewed by a stronger one, never the other way around.

The intended flow for non-trivial work: `/brainstorm` (decide *what* and *whether*) → `/feature` (build it through the gated pipeline) → `/commit`, with `/debug` and `/consult` as escalations along the way.

## Quick Install

Run this one-liner from the root of your project:

```bash
curl -fsSL https://raw.githubusercontent.com/mbocek/claude-support/main/install.sh | bash
```

This downloads the `.claude` directory into your current working directory. Requires `curl` and `jq`. After installing into a new project, run `/bootstrap-project` to set up the `CLAUDE.md` contract the agents rely on.

## Agents

| Agent | Model / effort | Access | Role |
|-------|----------------|--------|------|
| `scout` | haiku / low | read-only | Fast codebase reconnaissance — locates code, maps conventions, feeds context to the other agents |
| `architect` | opus / high | read-only | Design and implementation planning — boundaries, contracts, data flow, ordered steps, risks |
| `implementer` | sonnet / high | write | Writes code in any stack, following the plan and the conventions of the surrounding codebase |
| `test-engineer` | sonnet / medium | write | Writes behavior-focused tests using the project's test framework and preferences |
| `code-reviewer` | opus / high | read-only | Verification gate — correctness, concurrency, resources, contracts, test quality |
| `security-reviewer` | opus / high | read-only | Adversarial review of security-sensitive surfaces — injection, authN/Z, secrets, trust boundaries |
| `debugger` | opus / xhigh | write | Root-cause analysis: reproduce → hypothesize → bisect → confirm; fixes only on request |
| `docs-writer` | haiku / low | docs only | READMEs, changelogs, runbooks, API docs — verified against the actual code |
| `fable-consultant` | fable / high | read-only | Escalation-only second opinion for stuck problems and high-stakes arbitration; invoked via `/consult` |

## Commands

| Command | Description |
|---------|-------------|
| `/brainstorm` | Sparring-partner ideation for the phase *before* the "what" is decided — agent panel kickoff, converge/map modes, opt-in devil's advocate, ends in a decision artifact that feeds `/feature` |
| `/feature` | End-to-end pipeline: scout → architect → **plan approval** → implementer → test-engineer → review loop (code-reviewer + security-reviewer when relevant) → docs. Accepts a `/brainstorm` artifact as input — decided items are givens, open questions must be settled explicitly |
| `/debug` | Structured debugging: collect evidence → reproduce → hypothesize → bisect → present root cause; fix (+ regression test + review) only on approval |
| `/consult` | Escalation to `fable-consultant` with an enforced briefing protocol (problem, attempts, constraints, the question) and a gate against casual use |
| `/bootstrap-project` | Audits or creates the project's `CLAUDE.md` against the contract template — the glue between generic agents and a concrete stack |
| `/commit` | Create a git commit following [commitizen](https://commitizen-tools.github.io/commitizen/) conventions (`<type>(<scope>): <description>`) |

## The CLAUDE.md contract

Agents are generic; projects are not. Each project's `CLAUDE.md` supplies what the agents need: stack, exact build/test/lint commands, layout, conventions, boundaries (what agents must never touch), and what "done" means. The section checklist lives in [`.claude/templates/claude-md-template.md`](.claude/templates/claude-md-template.md), and `/bootstrap-project` fills or audits it per repo.

## Agent memory

Agents with `memory: project` persist durable, non-obvious findings under `.claude/agent-memory/<agent-name>/` following the shared protocol in [`.claude/agent-memory/_shared/protocol.md`](.claude/agent-memory/_shared/protocol.md) — expensive insights (a debugger root cause, a consultant verdict) shouldn't need to be bought twice.

## Manual Installation

If you prefer not to use the install script:

```bash
# Clone and copy
git clone git@github.com:mbocek/claude-support.git /tmp/claude-support
cp -r /tmp/claude-support/.claude .claude
rm -rf /tmp/claude-support
```

Or symlink for automatic updates:

```bash
git clone git@github.com:mbocek/claude-support.git ~/claude-support
ln -s ~/claude-support/.claude .claude
```
